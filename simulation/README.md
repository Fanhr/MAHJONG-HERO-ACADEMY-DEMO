# 数值验证模拟：摸牌节奏与卡池容量

对应策划方案《英雄麻将_核心策划方案.md》的数值验证脚本，回答"假定任一玩家都不使用技能"前提下的三个问题。

## 运行方式

```bash
pip install mahjong   # 依赖：MahjongRepository/mahjong，提供向听数(shanten)计算
python3 mahjong_balance_sim.py
```

脚本会自动使用多进程并行加速蒙特卡洛模拟（(2)部分默认 6000 局采样），完整输出见 `results.txt`。

## 核心假设

- 标准四人立直麻将：136张牌，王牌(死墙)14张不参与摸牌，起手庄家14张/闲家13张，活牌墙 = 136-53-14 = 69张。
- (2)(3)部分**只模拟门清打法（不吃/碰/杠）**，每回合用"向听数最小化 + 接近听牌时按进张数(ukeire)决胜"的贪心策略选择打出的牌，逼近"最快听牌"的打法上限。
- **重要限制**：由于不允许吃碰杠，模拟得到的"最快胡牌"速度会比真实允许开局吃碰的最优打法**更慢**（即得到的期望剩余牌数比真实值偏小），这是为控制实现复杂度做出的保守简化，实际数值可作为下界参考。
- **抽卡规则（当前版本）**：每2巡（自己的摸牌次数）触发一次抽卡事件，每次揭示3张、选1张保留，其余2张视为从"本局可抽范围"移出、不放回。对"是否曾遇到目标稀有卡"这一问题，"选1保留"不改变概率——等效于把每次事件揭示的3张牌，视为一次连续的不放回抽取（详见脚本 `acquisition_effective_draws()` 的注释推导）。

## 结果摘要（详见 results.txt）

| 问题 | 结果 |
|---|---|
| (1) 荒牌情况下四人平均摸牌次数 | 69/4 = **17.25次**（分配为 18/17/17/17） |
| (2) 全员最快听牌打法下，首位和牌时牌墙期望剩余张数 | **19.03张**（6000局蒙特卡洛，95%置信区间 ±0.49；中位数17；荒牌(无人和牌)占比54.15%） |
| (3) 满足"整局命中率<80%，(2)检查点命中率≈50%"的卡池容量 M（每2巡抽3选1规则） | K=2(纯SSR)：**M≈62张**；K=3：M≈88张；K=4：M≈115张 |

### 抽卡规则变更前后对比（"每4巡抽1张" → "每2巡抽3选1"）

| | 旧规则 | 新规则 |
|---|---|---|
| 整局等效抽取次数 n_total | 4 | **24**（8次事件×3张） |
| (2)检查点等效抽取次数 n_early | 3 | **18**（6次事件×3张） |
| K=2时满足目标的卡池容量M | ≈11张 | **≈62张** |

新规则触发更频繁（2巡 vs 4巡）且单次揭示3张（vs 1张），综合导致"遇到目标卡"的机会大幅增加（等效抽取次数从4/3提升到24/18，约6倍）。要维持同样的"检查点≈50%、整局<80%"概率目标，卡池容量需要从约11张扩大到约62张（K=2时），否则同样容量下命中率会远超设计目标（例如仍用11张卡池，检查点命中率会飙升到约85%以上）。

## (3) 与卡池"30%/70%分流"设计的整合注意事项

策划方案 4.2 节规定：抽卡事件有 30% 概率触发私有子池（如英雄专属牌）、70% 概率触发公共池。若 M 特指该私有子池的容量，则实际"命中该子池"的抽取次数会被 30% 稀释——用二项分布叠加超几何分布重新计算后（`prob_at_least_one_hit_thinned_v2()`）：

| 私有子池容量 M | 整局命中率 | 检查点命中率 |
|---|---|---|
| 6（贴近"每英雄5~8张"建议规模） | 90.3% | 82.2% |
| 16 | 65.1% | 52.9% |
| 20 | 56.3% | 44.8% |

可见：在新的"每2巡抽3选1"节奏下，即使叠加30%分流稀释，容量在16~20张左右就能落在检查点≈50%附近——这与旧规则下需要压缩到约3张（几乎等于SSR本身）形成鲜明对比，说明"每2巡抽3选1"这个新节奏显著改善了此前"分流机制与50%目标冲突"的问题，为专属牌池维持"5~8张"甚至更大规模留出了更充裕的设计空间。
